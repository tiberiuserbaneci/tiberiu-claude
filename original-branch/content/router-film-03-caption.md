Three things to keep straight if this gets revised:

## LINKEDIN CAPTION

Most founders are paying frontier prices for shallow questions.
Not because Claude is wrong. Because picking the model was left to them.

- - -

Every tool opens with the same question: which model do you want. It looks like control and
it is really a tax, because nobody knows the answer before they see the output. So you either
default to the cheapest and get thin work, or default to the top of the shelf and burn credits
on lookups. I stopped choosing and made the routing the product's job instead.

- - -

→ One input, plain English. No model picker, no tier dropdown, no effort dial. You describe
the job the way you would to a person.

→ The router reads the job before it answers. Volume, depth, what it costs to be wrong, and
how fast you need it. Four reads, before a single token of output.

→ Then it picks two things, not one: the model and the effort. Haiku 4.5 on low for lookups
and classifying. Sonnet 5 on high, the standing default for real execution. Opus 5 on xhigh
for judgement that is actually hard. Fable 5 on max when being wrong is expensive.

→ The spread is 1x, 3x, 5x, 10x on published list prices. Haiku 4.5 runs about 3x cheaper
than Sonnet 5 on work that never needed more, and Fable 5 costs 10x what that lookup costs.

→ You almost never reach the top. Opus 5 takes the same hard judgement at half the price of
Fable 5, so Fable stays for the long-horizon jobs and Opus does the work.

- - -

The lesson underneath is that model choice was never a user preference. It is a routing
problem, and routing problems belong to the system, not the person using it. Every minute a
founder spends deciding between Haiku and Opus is a minute spent on the tool instead of the
work, and the decision was never theirs to make well. Take it off the screen and the tool
stops asking you to be its operator.
