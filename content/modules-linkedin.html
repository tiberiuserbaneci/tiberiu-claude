Ultron Platform · Provider Modules · Spec
Most AI hardcodes its tools.
Ultron ships them as modules.
A provider module is one file: schemas, executors, status labels, a connection gate. The dispatcher checks modules first, then falls back to the native catalog. Two ship today, hitl and stripe.

The contract types.ts
interface ToolModule {
  provider: string
  schemas: OpenAIFunctionSchema[]
  executors: Record<string, ToolExecutor>
  statusLabels?: Record<string, StatusLabelFn>
}
Four fields. provider is the id in logs and status labels. schemas are what the model sees. executors run the call. statusLabels render a verb phrase while it runs.
The dispatcher registry.ts
const MODULES = [hitlModule, stripeModule]
const idx = new Map()
for (const m of MODULES)
  for (const [n, fn] of entries(m.executors))
    idx.set(n, { fn, provider: m.provider })

getModuleSchemas()  // flatten every schema
dispatchModuleTool(name, args, ctx)  // -> string | null
Index built once at load, so dispatch is constant time. The dispatcher is dumb on purpose, it only finds the executor by name.
Call lifecycle chat-tools.ts
const mod = await dispatchModuleTool(name, args, ctx)
if (mod !== null) return { result: mod }
// else fall through to the legacy switch
Module first, then the historical switch that still owns every un-migrated name. Migration is one tool at a time; both paths coexist.

Why a module not the native catalog
The native catalog grew into one thousand-line file
A module adds new tools without making it longer
It owns its surface: schemas, executor, status, gate
The dispatcher is dumb on purpose: finds the executor by name
New modules ship without touching shared code
The contract is small enough to fit one file
New tools should ship as modules, not the catalog
Native stays for the existing surface and shared helpers
Schema OpenAI function calling
{ type: "function", function: {
  name: "stripe_list_customers",

  parameters: { type: "object", properties: {
    email:  { type: "string" },

The model only sees the schema. Keep the description short and operational, selection leans on it more than any docstring.
Executor async, returns string
async function stripeListCustomers(ctx, args) {
  const stripe = await getStripeFor(ctx.userId)
  if (!stripe) return "Stripe not connected."
  const list = await stripe.customers.list({
    email: args.email, limit: clamp(args.limit,1,100) })
  return JSON.stringify(list.data.map(pick))
}
