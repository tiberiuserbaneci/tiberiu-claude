The real difference
DEMO WORKS ONCE.

Demo agent
  • Happy path only
  • No error handling
  • No memory
  • Crashes on bad input
Production agent
  • Handles edge cases
  • Retries + fallbacks
  • Persistent memory
  • Gracefully degrades
The checklist
6 THINGS THAT
MUST BE TRUE.
1
Handles tool failures gracefullyretry, fall back, or report. Never crash silently
2
Every run is observablesee every tool call on any past session
3
Memory persists across sessionsusers never re-explain context
4
Guardrails block dangerous actionshigh-risk tools need human approval
5
It stays within token limitscompresses history instead of cramming
6
You can evaluate it systematicallyknow better or worse before it ships
Step 1 · The foundation
PICK THE RIGHT MODEL.
WRITE THE RIGHT PROMPT.
1
Match model to taskHaiku for routing, Sonnet for reasoning, Opus for the hardest calls
2
The system prompt is load-bearingspecific prompts produce predictable agents
3
A context file, read every sessionconventions, rules, preferences. It stops asking
Most failures are prompt failures, not model failures.
Step 2 · Tools
TOOLS FAIL.
PLAN FOR IT.
every tool call · retry ×3 → timeout → fallback
"Search unavailable. Try a different approach."
the agent works around it, never crashes
Keep tools focused
  • One tool, one job
  • Fewer than 8 per agent
Never retry 4xx
  • Retry 5xx + network only
  • 4xx just burns tokens
Step 3 · Memory
AGENTS WITHOUT MEMORY
START OVER.
short-termWorking memory, compressed before it overflows semanticVector memory, the foundation of RAG long-termPreferences and decisions, across sessions skillLearned conventions, loaded every session
Memory turns a one-shot tool into a system users trust.
Step 4 · Observability
IF YOU CAN'T SEE IT
YOU CAN'T FIX IT.
tracing: on · 2 lines of setup
every run → every tool call · every token · every decision
+
Track four numberslatency per step, tokens, tool success rate, answer quality
Without traces, debugging a silent failure means guessing.
