· The Checklist
6 Things
That Must
Be True.
Before you call an agent "production-ready", it needs to pass all six. Not five. Six.
1
It handles tool failures gracefully
APIs go down. Networks time out. Your agent must retry, fall back, or report, never crash silently.
2
Every run is observable
You can see exactly what the agent did, which tools fired, and what the model returned, on any past session.
3
Memory persists across sessions
The agent remembers what it did last time. Users do not re-explain context on every new conversation.
4
Guardrails block dangerous actions
High-risk tools, delete, send, charge, need human approval before they fire. Not optional.
5
It stays within token limits
Long sessions eat context. The agent compresses history intelligently instead of cramming the window.
6
You can evaluate it systematically
You have a test suite. You know if a change made the agent better or worse before it ships.

· Step 1 · The Foundation
Pick the Right
Model.
Write the
Right Prompt.
The model and the system prompt are the brain of your agent. Get these wrong and no amount of tooling will save you.
1
Do not default to the biggest model
Match model to task. Claude Haiku is fast and cheap for simple routing. Sonnet for nuanced reasoning. Opus for the hardest tasks. Stay model-agnostic.
2
The system prompt is load-bearing
Define the agent's role, constraints, tone and tool rules in a clear system prompt. Vague prompts produce vague agents. Specific prompts produce predictable agents.
3
Use a context file read every session
Project context, conventions, team preferences, business rules, loaded on every run. The agent stops asking what it already knows.
Rule of ThumbStart with a small model + a great prompt. Upgrade the model only when the prompt ceiling is genuinely hit. Most failures are prompt failures, not model failures.

· Step 2 · Tools
Tools Fail.
Plan For It.
Every tool call in production will eventually fail. Wrap every single one with retry logic, a timeout and a fallback before your agent ships.
Wrap every tool call · retry patternfrom tenacity import retry, stop_after_attempt, wait_exponential

# every call gets retries, a timeout and a fallback
@retry(stop=stop_after_attempt(3), wait=wait_exponential(multiplier=1, max=10))
def search_web(query: str) -> str:
    try: return tavily.search(query)
    except Exception as e:
        return "Search unavailable. Try a different approach."
# the agent sees the error as text and works around it, never crashes
+
Keep tools focused
One tool, one job. Fewer than 8 tools per agent. Vague tools mean the wrong tool gets chosen. Clear descriptions, reliable routing.
!
Never retry on 4xx errors
Retry on 5xx and network failures only. Retrying a 400 Bad Request just burns tokens faster.

· Step 3 · Memory
Agents Without
Memory
Start Over.
An agent that forgets every session is not useful in production. Memory is what turns a one-shot tool into a system users trust.
Short-Term
Working Memory
The active conversation window. Compress it before it overflows, checkpoint the thread, never lose the live context.
Semantic
Vector Memory
Documents and knowledge searched by meaning, the foundation of RAG. Pinecone, pgvector, Weaviate.
Long-Term
Persistent Memory
Survives across sessions. Preferences, project rules, past decisions. Mem0, LangGraph Store, Zep.
Skill
Learned Conventions
User corrections, patterns and team rules stored in a context file, loaded every session.

· Step 4 · Observability
If You Can't See It
You Can't Fix It.
Every agent decision in production must be traceable. Without logs and traces, debugging a silent failure means guessing.
Enable tracing · 2 linesimport os
os.environ["TRACING_V2"] = "true"
os.environ["TRACING_API_KEY"] = "your key"
# every agent run is now auto-traced: every tool call, every token, every decision

import logfire
logfire.configure()
# one logfire line for structured logs on top
+
What to track
Latency per step, tokens used, tool success rate, answer quality. The four numbers that explain every failure.
+
Tools that do it
LangSmith, Logfire, Arize. All integrate in 2 lines. Full trace trees, structured search over every run.

· Step 5 · Safety
The Agent Decides
What.
You Decide
What's Safe.
The model picks the action. Your guardrails decide if it is allowed. These are architecturally separate, and they must be.
1
Input guardrails
Validate user requests before the agent acts. Block harmful, out-of-scope or malformed inputs at the front door.
2
Human-in-the-loop · pause before the action
High-risk tools (send email, delete file, charge card) pause the agent and wait for human approval. It resumes with full context, exactly where it stopped.
3
Output guardrails
Final check before the result reaches the user. Catch hallucinations, policy violations or incomplete answers, before they ship.
Start HereDefault to supervised: the agent acts, a human approves the high-risk steps. Earn full autonomy by proving reliability over time.

· Step 6 · Evals
Test Your
Agent Like
Software.
You would not ship code without tests. Do not ship agents without evals. Evals tell you if a change made the agent better or worse, before your users find out.
1
Build a golden dataset
50-100 real inputs with expected outputs. Every change to the agent runs against this. Green means ship. Red means fix.
2
Test failure modes specifically
Bad inputs, API timeouts, ambiguous queries, very long sessions. If it can happen in production, test it before production.
3
Use LLM-as-judge for quality
For open-ended answers, a second model scores accuracy, completeness and relevance. Scales to thousands of evals per run.
ToolsLangSmith Evaluations · Braintrust · OpenEvals · Ragas (for RAG) · pytest with LLM assertions
