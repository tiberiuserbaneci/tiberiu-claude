PROJECTS VS SKILLS
Two tools.
Different jobs.

People mix these up and then wonder why nothing sticks. The split is simple.

SKILL
A recipe
for a repeatable task. Same steps, same output, every run.
e.g. cold-email, ICP score
PROJECT
A workspace
for ongoing work. Holds the memory of what came before.
e.g. Q3 Outbound, one client
Use a Project when the work needs memory of what came before.
Reach for a Skill when you repeat the same task and want one fixed output.
The best setups stack both: Skills run the reps inside a Project that remembers.
WHEN TO USE WHICH
Chat, Project,
or Skill?

One quick rule for each, so you stop forcing every job into a fresh chat.

CHAT
Thinking
A one-off question. Nothing to remember after.
PROJECT
Doing
Ongoing work that compounds. A client, a quarter, a campaign.
SKILL
Repeating
The same task again. One fixed output every time.
A simple folder structure carries it: /reference · /analysis · /deliverables.
